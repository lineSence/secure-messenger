## SQL-модель CHAT-02

В реальном приложении `row` зашифрован. Здесь `mine` — явное синтетическое поле: модель проверяет только SQL LIMIT/порядок и последующий подсчёт, не SQLiteOpenHelper, Keystore или дешифрование.

```python
import sqlite3
c = sqlite3.connect(":memory:")
c.execute("CREATE TABLE messages(id INTEGER PRIMARY KEY, contact INTEGER, mine INTEGER)")
c.executemany("INSERT INTO messages VALUES(?,?,?)",
              [(n, 1, 0) for n in range(1, 602)])
h = c.execute(
    "SELECT id FROM messages WHERE contact=? ORDER BY id DESC LIMIT ?",
    (1, 500)).fetchall()
assert len(h) == 500 and min(x[0] for x in h) == 102
c.execute("DELETE FROM messages")
c.executemany("INSERT INTO messages VALUES(?,?,?)",
              [(n, 1, 0 if n == 1 else 1) for n in range(1, 502)])
rows = c.execute(
    "SELECT id,mine FROM messages WHERE contact=? AND id>? ORDER BY id DESC LIMIT ?",
    (1, 0, 500)).fetchall()
assert sum(x[1] == 0 for x in rows) == 0
assert c.execute("SELECT COUNT(*) FROM messages WHERE mine=0").fetchone()[0] == 1
```

Результат: из 601 входящего видны 500, самый ранний видимый id=102; одно входящее перед 500 исходящими не входит в подсчёт ограниченной выборки. Соответствие SQL настоящему коду проверено по `MessageStore.kt:88–125,225`, вызовам `ChatHub.history/markRead` и `ChatScreen`.

## Контраст UI-03

Точные значения из `Theme.kt`, а не из сглаженных пикселей снимка:

```python
def lum(h):
    s = [int(h[i:i+2], 16) / 255 for i in (0, 2, 4)]
    linear = [v / 12.92 if v <= 0.04045 else ((v + 0.055) / 1.055) ** 2.4
              for v in s]
    return sum(a*b for a, b in zip(linear, [0.2126, 0.7152, 0.0722]))

for fg, bg in [("4FAE4E", "E1F8CF"), ("8A939E", "FFFFFF"),
               ("FFFFFF", "2F8AE5"), ("9FC6EC", "2B5278")]:
    lo, hi = sorted([lum(fg), lum(bg)])
    print(f"#{fg} / #{bg}: {(hi+0.05)/(lo+0.05):.3f}:1")
```

```text
#4FAE4E / #E1F8CF: 2.472:1
#8A939E / #FFFFFF: 3.112:1
#FFFFFF / #2F8AE5: 3.567:1
#9FC6EC / #2B5278: 4.558:1
```

Порог 4.5:1 используется из действующего проектного `wiki/references/ux-guidelines.md:10–13`. В этом аудите не проводилась новая проверка внешних стандартов и не заявляется сертификация доступности.

## Обязательный последующий Android-прогон

- Два телефона, включая Android 12 и 13+: приглашение, QR, «Рядом», отказ разрешений, отключение Bluetooth и возврат из Settings.
- Home/блокировка с открытым чатом; входящее сообщение при сохранённой Activity; корректные уведомления и непрочитанное.
- Ошибки SQLite/Keystore до и после durable enqueue; черновик, повтор, отсутствие дублей; crash/failure при удалении.
- История >500 строк, непрочитанные среди исходящих, прокрутка вверх при обновлении другого чата.
- Реальные ModalBottomSheet и IME, ширины 320/360/368 dp, малая высота/landscape/split-window, fontScale 1/1.3/2, обе темы.
- TalkBack: роль и состояние switch/tab, шаги доставки, подписи заполненных полей и ошибок; bounds фактических touch targets.
- Пары макет/Compose одинаковых состояний и полезной области экрана. Проверка v16 отдельно от унаследованного стиля v14; отсутствие согласования нельзя выводить только из устаревшей wiki.

APK, JVM/Gradle-наборы, instrumentation, реальные телефоны, runtime TalkBack/IME и пиксельная сверка Android **не выполнены**. Аудит не является release approval и не гарантирует отсутствие других UX/UI-дефектов.
