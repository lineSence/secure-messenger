# Статус реализации находок оптимизации

Исходный аудит — report.md, baseline 889f5f4. Это **первый совместимый пакет**, не реализация всех 18 пунктов и не новая версия wire. Запрос владельца — реализовать оптимизации и сравнить две версии по 5 минут. Пакет слит через PR #94 при зелёном ci-ok (merge 05d14cc). Сравнение двух 300-секундных прогонов и выявленная TTL-регрессия — `wiki/audits/2026-10-15-relay-ab/report.md`. Все 18 пунктов не закрыты.

| Находка | Что сделано в пакете | Что остаётся |
|---|---|---|
| OPT-01 | Индекс ближайшего срока вместо полного обхода живых очередей; один таймер на очередь | Одновременно истёкшие объекты всё ещё обрабатываются под общим lock; нужна bounded/incremental очистка |
| OPT-02 | Уведомления WAIT по recipient ID, регистрация до повторной проверки, удаление подписок после выхода; нет пересканирования списка на каждый tick | ОС-потоки и 100-мс peek отмены остаются |
| OPT-03 | Общая квота количества сообщений, очистка пустой ёмкости deque, настройки | Не полный учёт RSS/allocator/input/output/подписок; защита всех пиков не доказана |
| OPT-04 | Уменьшена работа в lock: нет копирования блоба, подписи GUEST | Шардинг Store/локов не реализован |
| OPT-05 | Без изменений | Событийный runtime не реализован; выбор зависимости/модели требует отдельной реализации и проверок |
| OPT-06 | Проверяемая конфигурация ограничений | Входные memory reservations, защита от idle/slow насыщения на уровне прокси не реализованы |
| OPT-07 | Arc неизменяемого Vec, ответ из отдельных slices через write_vectored, без полных промежуточных копий payload | Сетевые/ядровые копирования не исчезают; проверять под большим числом одновременных отправок |
| OPT-08 | HTTP take дополняет свой буфер без rest→out копии | Read-body растёт постепенно; bounded pool/заряд capacity не реализованы |
| OPT-09 | Подпись GUEST вне store-lock, отдельная сериализация выдачи и повторная проверка билета до публикации | Отдельный bounded CPU-пул не добавлен |
| OPT-10 | Кеш публичного гостевого ключа, без кеша авторизаций | Подготовка root keys и set отзыва не реализованы |
| OPT-11 | Квоты/TTL/тайм-ауты доступны из окружения; проверка значений | Гостевой лимит и signed per_hour сохраняются; массовое восстановление отдельно не решено |
| OPT-12 | Wire v1 сохранён | Batch/окно доставки — спецификация и новая согласованная совместимость, не скрытая правка v1 |
| OPT-13 | Удалена лишняя копия тела HTTP | Курсор pending/head parser не изменён |
| OPT-14 | Без изменений | Полный конфиг/проверка nginx и реальный VPS не входят в выполненное |
| OPT-15 | Server::stop закрывает активные сокеты, ожидает освобождения до 5 с | SIGTERM/graceful drain основного бинарника не добавлен |
| OPT-16 | Без изменений | Маршрутизация, несколько RAM-узлов и HA не реализованы |
| OPT-17 | Клиент продвигает часть после успешной обработки и ACK, тест горячих частей | Пустые части всё ещё могут ждать последовательно; на телефонах не проверено |
| OPT-18 | Настройки release/аллокатор/атомики не менялись | Нет доказанного основания включать LTO или менять аллокатор |

RAM-only и запрет телеметрии сохранены. Нет новых зависимостей, unsafe и ослабления CI. Слияние выполнено после зелёного ci-ok точного head SHA; рабочий VPS не обновлялся. Сравнение до/после — диагностическое на одном хосте; не паспорт максимальной мощности и не проверка VPS/Android в реальной сети.
