# Реализация: шардирование, reactor и batch v2

База: `435d40a40eda487ede80da372b785ed8f02cc6d7` (main после PR #95). Источник — поручение владельца продолжить реализацию, затем провести тесты и сравнительный анализ; дата стенда 2026-10-15. **Полный исходный план не завершён:** межмашинная маршрутизация и HA остаются открытыми.

## Реализовано

- Engine с независимыми Mutex<Store>, по умолчанию 16 шардов. SEND выбирает шард по ID отправителя; FETCH/ACK/DEL — по `sender_id(recipient)`, то есть обе стороны одной очереди попадают в тот же Store. Тест удерживает блокировку горячего шарда и завершает SEND в другом.
- Очереди, сообщения и байты имеют **общие атомарные квоты**, не квоты × число шардов. ACK, DEL и expiry освобождают логические ресурсы ровно один раз; фактическая память payload остаётся зарезервирована до последнего Arc. Глобальные/per-pass ограничения NEW и билетов — отдельная маленькая control-plane блокировка, без SEND/FETCH/ACK в ней.
- Общее пространство capability не допускает `recipient новой очереди == sender чужой очереди`, в том числе между шардами. Namespace-reservation освобождает свой mutex **до** взятия Store; удаление может освобождать namespace под Store без обратного порядка блокировок. High-water ёмкость namespace зарезервирована отдельно.
- Mio readiness reactor, по умолчанию **2 фиксированных worker-потока**. Нет потока на соединение и 100-мс socket peek для WAIT. Глобальный предел соединений/WAIT и резерв четверти слотов сохранены. Deadline — индекс из одного таймера на соединение, а не полный обход всех соединений каждый tick.
- Адресные WAIT: subscribe-before-recheck, слияние повторных уведомлений в один pending token, уникальные не переиспользуемые token до checked overflow. Чужие очереди не будят все WAIT; отключение/stop закрывает сокеты и освобождает permits.
- Ограниченный цикл чтения/записи на событие, backpressure и один ограниченный pending frame у WAIT. На медленной отправке интерес только WRITABLE: непрочитанный pipeline не заставляет reactor крутиться на READABLE. Переполнение ограниченного pending input закрывает соединение.
- Фоновая bounded cleanup выполняется одним worker, не отдельным потоком на клиента. Следующая порция 256 шагов после до 10 мс при backlog или до 1 с без него. Шарды и control обслуживаются круговым порядком.
- Явный batch wire v2: `wiki/architecture/relay-batch-v2.md`, codec/reference client, сервер, malformed/partial-failure/response-budget тесты и fuzz. v1 и Kotlin не переключены скрыто.
- Новая конфигурация: `SM_RELAY_IO_WORKERS`, `SM_RELAY_STORE_SHARDS`; положительные, shards — степень двойки. Конечный бюджет RAM проверяет произведения и переполнение до создания workers/шардов.

## Память и остаточные ограничения

Runtime-резерв: `connections × (4 × MAX_BLOB + 64 KiB) + io_workers × 2 MiB + shards × 2048 + 8 MiB`. Стек резервируется **на worker**, не на соединение. Это консервативный admission, не доказательство абсолютного hard RSS: allocator/retained capacities/ОС остаются под внешним MemoryMax и требуют отдельного заполнения/churn/slow-reader профиля. Payload, metadata, namespace и исходящие Arc продолжают использовать общий Budget.

Одна горячая очередь остаётся последовательной; worker занят вычислением подписи/проверки фиксированного пропуска, пока операция не завершится. Смена числа шардов — внутреннее размещение при перезапуске RAM-only процесса, не миграция работающего кластера. Внешняя производительность зависит от профиля, а не только числа threads.

## Проверка поставок

Mio =1.2.4, default-features=false, только net/os-poll; log feature не включён. Новые транзитивные записи — wasi и windows-sys для целевых платформ; общие старые зависимости сохранены. cargo-vet принимает существующие доверительные записи Mozilla/Bytecode Alliance/ISRG, **суженные до дня публикации закреплённых версий**: Mio user-id 6025, wasi user-id 1. Это не независимый просмотр всего кода библиотек и не доверие будущим релизам. Новых exemptions и ослаблений CI нет. Источники/даты — `wiki/references/relay-runtime-dependencies.md`.

## Пока не реализовано

- Многоузловая маршрутизация и передача владельца очереди/правил пропуска между машинами. Локальный shard selector — **не** сетевой router и не горизонтальный кластер.
- Consensus/HA 2/3, выборы, peer RPC, возвращение RAM-only learner и ограниченное восстановление подтверждённого префикса.
- Среди проверенных в этом прогоне текущих импортируемых cargo-vet источников (Bytecode Alliance, Embark, Google, ISRG, Mozilla, Zcash) не найдено записей audits/trusted для openraft/raft/raft-proto. Это **не доказательство отсутствия любых аудированных решений**. Нельзя добавить exemption или собственную неподтверждённую запись safe-to-deploy ради CI. Следующий шаг HA — выбрать/проверить consensus-библиотеку и state-machine/peer-security/restart design; новый доверительный обход требует отдельного принятого ADR. Простое копирование SEND на два адреса не добавлено.
- Полный RAM-pressure/длительный soak, proxy+TLS/WAN, реальные телефоны и окончательная фиксация узла. Две 5-минутные версии этого пакета будут описаны отдельно в report.md только после фактических прогонов.
