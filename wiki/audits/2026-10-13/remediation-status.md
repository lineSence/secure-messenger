## Итог

Это завершённая инвентаризация интегрированных patches, **не полное закрытие 23 ID**, не release verdict и не разрешение на merge. PR остаётся Draft. Main напрямую не менялся, проверки не ослаблены, известный debug signing key не заменён.

«Реализовано» означает изменение корневого механизма в коде; «частично» — mitigation с оставшейся границей; «открыто» — исправления нет. Отсутствие настоящего Android fault/kill/upgrade теста не превращается в подтверждённое закрытие. Таблица ниже относится к `206c231`; продолжение и новые проверки выделены отдельно.

Префиксы путей: **A/** — `android/app/src/main/java/dev/sm/messenger/`; **T/** — `android/app/src/test/java/dev/sm/messenger/`; **R/** — `crates/`. Регрессии прочитаны независимым read-only субагентом; координатор отдельно запустил Rust workspace, изолированные JVM-наборы выполнили другие субагенты. Это не ансамбль разных моделей.

## Продолжение после остановки координатора

1. **Cached-card egress:** на `8682c61` LinkCard tag6 сохранялся до SEND. После обновления `206c231` `retryIn` отправлял journal без проверки формата; строгий входящий `decodeOut` не предотвращал раскрытие bytes узлу. Теперь `InviteLinks.preparedRetry` допускает Card только через настоящий `decode(frame) is PairMessage.SealedLinkCard`. Legacy/malformed/другие типы не отправляются; invitation/card/ownership rows и keys не удаляются. Reply сохраняет приоритет, стадия Ask ждёт согласия. Это перекрывает старый cached egress, **не миграция и не полное закрытие AUD-16**. Три новые KV-регрессии проверяют ветви и сохранность с подставленным validator. Дополнительно выполнены 3 host FFI-теста: реальный UniFFI/JNA `pairFrameDecode` → production `preparedRetry` → fake SEND, после повторного открытия journal. Native tag6 и malformed дают SEND=0; структурный tag7 даёт SEND=1 с теми же bytes. Это не полный InviteFlow/Android/TLS тест; sealed fixture проверяет framing, не GCM authentication (последняя проверяется отдельными Rust codec tests).
2. **Диагностика доставки:** добавлены ранние sender результаты и `ChatGather Start`, с существующими enum-кодами; target selection/backoff/crypto не менялись. `RelaySendLoop Ok` означает окончание локального прохода, не доставку. Подробный разбор и воспроизведение: [build 481](delivery-diagnostics.md). Причина конкретного отказа на телефоне пока не доказана.
3. **INT-PAIR-CANCEL:** независимый integration pass нашёл окно после durable accept сессии и до UI callback: закрытие экрана не видит результат в `started`/`accepted`, callback отбрасывается, а card ownership не является session ownership. Нельзя чинить это слепым `forget(address)` — он может удалить более новую сессию того же адреса. Добавлены отдельный durable `PairSessionOwners` journal и claim внутри общей accept-транзакции до UI publication. Успешный accept в любом lane и forget инвалидируют старый marker; stale UI/core work и cleanup проверяют UUID владельца. Reset/close освобождают pending sessions независимо от опубликованных maps и card cleanup. Сохранённый контакт не удаляется; failed cleanup остаётся retryable, restart recovery использует journal. Новые 10 JVM tests проверяют commit-before-UI/queued-callback cancellation, replacement owner/non-pairing accept, сохранённый контакт, rollback/retry и corruption. Port транзакционный in-memory, **не Android SQLite instrumentation**. Legacy orphan sessions без нового journal не удаляются наугад. Wire/crypto formats и UI этим исправлением не меняются.

## Блокеры и совместимость

- **AUD-04 открыт:** удаление контакта не отзывает ранее выданный общий beacon. Нужен принятый владельцем порядок ротации, доставки нового ключа оставшимся контактам и переключения/offline восстановления. Старый контакт по-прежнему вычисляет tokens и открывает наружный BLE-слой, но это не расшифровка Signal-сообщений.
- **AUD-16 частичен:** tag7 уже внесён прежним агентом, старые клиенты его не понимают, новый клиент отказывается от plaintext downgrade. ADR-151 не согласовывает этот wire-change: он предусматривает отсутствие изменений криптоформатов. Нужен отдельный ADR владельца и миграционная политика. Новое sealing не скрывает traffic/length и identity в последующем Signal PreKey Start.
- Pending Sent с legacy cached tag6 теперь fail-closed, без автоматического перевыпуска карточек/сессий. Pending rows без prepared frame не восстанавливаются автоматически. До принятой миграции нельзя обещать, что старые приглашения завершатся после обновления.
- Legacy prekeys без ownership не удаляются наугад; pinned/consumed keys не age-out. Ambiguous CT tombstones не становятся доказательством peer ACK; legacy empty/oversized snapshots отвергаются, не «спасаются» невалидным restore. SQLite schema v3/generic KV без bump не доказывает миграцию этих состояний.
- `RISK-DEBUG` остаётся: публичным постоянным ключом можно подписать поддельное debug-обновление; пользователь/ADB должен установить его поверх debug. Release package/key отдельно. Не подменять этот риск молчаливой сменой подписи с потерей тестовых данных.
- Нужны настоящие SQL/Keystore fault+kill, upgrade fixtures и два телефона/BLE/TLS. Зелёный CI не заменяет эти доказательные gates.
