## [CODE-NO-WEAKENING] Не ослаблять проверки без ADR
Правило: Не отключать и не ослаблять линты (`[workspace.lints]`, `clippy.toml`), правила `deny.toml`, `.semgrep/`, исключения cargo-vet, ИИ-ревью и шаги `ci.yml` без нового ADR, принятого владельцем. Исключение для ИИ-ревью — запись в `.github/ai-review-waivers.json` с обоснованием и тестом. `#[allow(...)]` — только точечно и с комментарием «почему».
Почему: ослабление проверки — самый дешёвый способ «пройти» CI для агента; ADR-15, ADR-20.

## [CODE-REVIEW-PROMPT] Ревью релиза — один готовый промпт
Правило: ИИ-ревью — только на релизе (ADR-53), первое — на `0.0.1-alpha` (ADR-57). На релиз — один промпт целиком, готовый к копированию; владелец запускает его 8 раз без изменений, каждый раз в новом чате; номер прогона — порядок записи в файле вердиктов, в промпте его нет. Не писать «то же, но замени X на Y» и не ссылаться на прошлые промпты. В промпте: релиз, полный SHA кандидата (`reviewed_head`), объём (diff от прошлого тега или весь код), путь к `.github/ai-review/INSTRUCTIONS.md`, файл вердиктов, формат ответа JSON на случай, если модель не может сделать коммит, и требование заново скачать файл перед записью и не удалять чужие записи. Модель и метку модели не указывать (ADR-57). Агент, который пишет код, сам ревью не делает и вердиктов не пишет; вердикты от владельца принимаются. В PR промпты ревью не выдаются.
Почему: модели в чате не знают своего имени и подписываются чужим (поправки владельца 2026-10-09); промпт с заменами даёт ошибки копирования (поправка владельца 2026-10-10); второй ревьюер однажды затёр запись первого; 48 промптов на релиз — слишком много, модели не важны (решения владельца 2026-10-10, ADR-54 отклонён, ADR-57).
Переносимость: проект

## [CODE-CI-WAIT-REVIEWS] Отменено (ADR-52, 2026-10-10)
Правило: Не действует. CI идёт на каждый push в PR, в том числе с одними вердиктами; ждать нужно `ci-ok` последнего коммита с двумя свежими ревью.
Почему: репозиторий публичный (ADR-51), минуты Actions бесплатны; ранний прогон показывает падения до прихода ревью (решение владельца 2026-10-10).

## [CODE-LOCAL-PRECHECK] Локальная проверка — с настройками репозитория
Правило: Проверяя код вне репозитория или новый workspace: (1) копировать `[workspace.lints]` из корневого `Cargo.toml` в черновой крейт; (2) cargo-deny — `cargo deny --manifest-path <путь> --config deny.toml check` (`--config` до `check`), path-зависимостям — точная `version`; (3) JSON вердикта ревью — `node -e "JSON.parse(require('fs').readFileSync(f))"` до пуша.
Почему: из inbox 2026-10-10, 3 случая: PR #12 упал в CI на `arithmetic_side_effects`, cargo-deny для `fuzz/` — ошибка разбора аргументов и бан wildcards (PR #11), битый JSON вердикта дал «ждём второе ревью» (PR #10).
Переносимость: общее (Rust)
