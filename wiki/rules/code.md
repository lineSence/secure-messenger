## [CODE-NO-WEAKENING] Не ослаблять проверки без ADR
Правило: Не отключать и не ослаблять линты (`[workspace.lints]`, `clippy.toml`), правила `deny.toml`, `.semgrep/`, исключения cargo-vet, ИИ-ревью и шаги `ci.yml` без нового ADR, принятого владельцем. Исключение для ИИ-ревью — запись в `.github/ai-review-waivers.json` с обоснованием и тестом. `#[allow(...)]` — только точечно и с комментарием «почему».
Почему: ослабление проверки — самый дешёвый способ «пройти» CI для агента; ADR-15, ADR-20.

## [CODE-REVIEW-PROMPT] Ревью релиза — готовые промпты с меткой и номером прогона
Правило: ИИ-ревью — только на релизе (ADR-53). Для каждой части релиза дать владельцу 8 готовых промптов: метки `reviewer-a`, `reviewer-b`, `reviewer-c`, `reviewer-d`, у каждой прогон 1 и 2. Каждый промпт — целиком, готовый к копированию; не писать «то же, но замени X на Y» и не ссылаться на прошлые промпты. В промпте: релиз и часть, полный SHA кандидата (`reviewed_head`), список путей части, путь к `.github/ai-review/INSTRUCTIONS.md`, файл вердиктов, метка для поля `"model"` и номер для поля `"run"`, формат ответа JSON на случай, если модель не может сделать коммит, и требование заново скачать файл перед записью и не удалять чужие записи. Имя модели модель не пишет — только метку из промпта. Агент, который пишет код, сам ревью не делает и вердиктов не пишет; вердикты от владельца (каждый прогон — новый чат с чистым контекстом) принимаются. В PR промпты ревью не выдаются.
Почему: модели в чате не знают своего имени и подписываются чужим (поправки владельца 2026-10-09); промпт с заменами даёт ошибки копирования (поправка владельца 2026-10-10); второй ревьюер однажды затёр запись первого; ревью только на релизах, 4 модели × 2 прогона — решение владельца 2026-10-10.
Переносимость: проект

## [CODE-CI-WAIT-REVIEWS] Отменено (ADR-52, 2026-10-10)
Правило: Не действует. CI идёт на каждый push в PR, в том числе с одними вердиктами; ждать нужно `ci-ok` последнего коммита с двумя свежими ревью.
Почему: репозиторий публичный (ADR-51), минуты Actions бесплатны; ранний прогон показывает падения до прихода ревью (решение владельца 2026-10-10).
