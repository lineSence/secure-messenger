# Правила: код и конвейер
Ключевые слова: код, CI, PR, линтер, clippy, проверка, слияние, main

## [CODE-CI-GREEN] В main — только через PR с зелёным `ci-ok`
Правило: Код (`crates/`, `fuzz/`, `.github/`, `scripts/`, `Cargo.*`, `deny.toml`, `supply-chain/`, `.semgrep/`) попадает в `main` только через PR, у которого итоговая проверка `ci-ok` зелёная. Красную проверку не обходить: исправить причину. Документацию (`wiki/`, `design/`, `memory/`) можно коммитить напрямую.
Почему: код пишут только ИИ-агенты (R-6), проверка — только автоматика (R-12); на бесплатном плане GitHub защита ветки для приватного репозитория недоступна — `wiki/references/ai-security-review.md`.

## [CODE-NO-WEAKENING] Не ослаблять проверки без ADR
Правило: Не отключать и не ослаблять линты (`[workspace.lints]`, `clippy.toml`), правила `deny.toml`, `.semgrep/`, исключения cargo-vet, ИИ-ревью и шаги `ci.yml` без нового ADR, принятого владельцем. Исключение для ИИ-ревью — запись в `.github/ai-review-waivers.json` с обоснованием и тестом. `#[allow(...)]` — только точечно и с комментарием «почему».
Почему: ослабление проверки — самый дешёвый способ «пройти» CI для агента; ADR-15, ADR-20.
