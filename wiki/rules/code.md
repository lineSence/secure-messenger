## [CODE-NO-WEAKENING] Не ослаблять проверки без ADR
Правило: Не отключать и не ослаблять линты (`[workspace.lints]`, `clippy.toml`), правила `deny.toml`, `.semgrep/`, исключения cargo-vet, ИИ-ревью и шаги `ci.yml` без нового ADR, принятого владельцем. Исключение для ИИ-ревью — запись в `.github/ai-review-waivers.json` с обоснованием и тестом. `#[allow(...)]` — только точечно и с комментарием «почему».
Почему: ослабление проверки — самый дешёвый способ «пройти» CI для агента; ADR-15, ADR-20.

## [CODE-REVIEW-PROMPT] Ручное ИИ-ревью — готовый промпт с меткой ревьюера
Правило: Когда PR ждёт ручного ИИ-ревью (режим `manual`), дать владельцу два готовых промпта: «A» для Opus 5.5 и «B» для GLM 5.3. Каждый промпт — целиком, готовый к копированию; не писать «то же, но замени X на Y» и не ссылаться на промпты прошлых PR. В промпте: ссылка и номер PR, полный SHA head (`reviewed_head`), путь к `.github/ai-review/INSTRUCTIONS.md`, формат ответа JSON на случай, если модель не может сделать коммит, и метка ревьюера для поля `"model"`: `reviewer-a` (Opus 5.5) или `reviewer-b` (GLM 5.3). Имя модели модель не пишет — только метку из промпта. Для слияния нужны свежие вердикты обеих меток по текущему head. Агент, который работает над проектом, сам ревью не делает и в `.github/ai-review/manual/` своих вердиктов не пишет. Вердикты от владельца (каждый раз новый чат с чистым контекстом) принимаются, в том числе для кода, написанного агентом: независимость обеспечивает чистый контекст.
Почему: модели в чате не знают своего имени и подписываются «Notion AI» или чужим именем; конвейер считает разные модели по полю `"model"`, а владелец различает ревью по метке из промпта, который сам отправил (поправки владельца 2026-10-09); промпт с заменами вместо полного текста даёт шанс ошибки при копировании (поправка владельца 2026-10-10).
Переносимость: проект

## [CODE-CI-WAIT-REVIEWS] Отменено (ADR-52, 2026-10-10)
Правило: Не действует. CI идёт на каждый push в PR, в том числе с одними вердиктами; ждать нужно `ci-ok` последнего коммита с двумя свежими ревью.
Почему: репозиторий публичный (ADR-51), минуты Actions бесплатны; ранний прогон показывает падения до прихода ревью (решение владельца 2026-10-10).
