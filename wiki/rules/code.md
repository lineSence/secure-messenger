Core-правило [CODE-CI-GREEN] (да владельца 2026-10-09) — в `AGENTS.md`. Подробности к нему:

## [CODE-NO-WEAKENING] Не ослаблять проверки без ADR
Правило: Не отключать и не ослаблять линты (`[workspace.lints]`, `clippy.toml`), правила `deny.toml`, `.semgrep/`, исключения cargo-vet, ИИ-ревью и шаги `ci.yml` без нового ADR, принятого владельцем. Исключение для ИИ-ревью — запись в `.github/ai-review-waivers.json` с обоснованием и тестом. `#[allow(...)]` — только точечно и с комментарием «почему».
Почему: ослабление проверки — самый дешёвый способ «пройти» CI для агента; ADR-15, ADR-20.

## [CODE-REVIEW-PROMPT] Ручное ИИ-ревью — готовый промпт с меткой ревьюера
Правило: Когда PR ждёт ручного ИИ-ревью (режим `manual`), дать владельцу два готовых промпта: «A» для Opus 5.5 и «B» для GLM 5.3. В промпте: ссылка и номер PR, полный SHA head (`reviewed_head`), путь к `.github/ai-review/INSTRUCTIONS.md`, формат ответа JSON на случай, если модель не может сделать коммит, и метка ревьюера для поля `"model"`: `reviewer-a` (Opus 5.5) или `reviewer-b` (GLM 5.3). Имя модели модель не пишет — только метку из промпта. Для слияния нужны свежие вердикты обеих меток по текущему head. Агент, который работает над проектом, сам ревью не делает и в `.github/ai-review/manual/` своих вердиктов не пишет. Вердикты от владельца (каждый раз новый чат с чистым контекстом) принимаются, в том числе для кода, написанного агентом: независимость обеспечивает чистый контекст.
Почему: модели в чате не знают своего имени и подписываются «Notion AI» или чужим именем; конвейер считает разные модели по полю `"model"`, а владелец различает ревью по метке из промпта, который сам отправил (поправки владельца 2026-10-09).

## [CODE-CI-WAIT-REVIEWS] Не запускать CI, пока ревью 1 из 2
Правило: Если в PR свежее ревью только одно из двух (`reviewer-a` или `reviewer-b`), CI не запускать: не перезапускать прогон, не пушить пустые коммиты и не ждать `ci-ok` — сначала нужно второе ревью по тому же head. Полный прогон — только когда ревью 2 из 2. CI делает это сам (ADR-28): push, где изменены только вердикты, при 1 свежем ревью задачи не запускает, `ci-ok` пишет «⏸ ждём второе ревью».
Почему: без двух ревью `ci-ok` всё равно красная, а полный прогон тратит до 40 минут Actions из 2 000 в месяц (указание владельца 2026-10-09).
