# Домашние узлы Windows/Linux без обязательного VPS и домена

Статус: **направление принято владельцем, реализация поэтапная**. Источник — текущий чат: нужны готовые бинарники Windows/Linux и простое поднятие на доступных домашних ПК; владелец разрешил раскрытие домашнего IP, потребовал работу без белого IP/доступа к роутеру, затем поручил документировать и начинать реализацию. Дата решения — 2026-10-14 по контексту чата; дата лаборатории — 2026-10-15 UTC. ADR-154, R-24. Это не объявление работоспособного CGNAT-транспорта или готового публичного релиза.

## 1. Целевой пользовательский сценарий

Скачать комплект под Windows x64 или Linux x64, проверить происхождение/подпись, распаковать, задать конечный бюджет RAM и доверенный открытый ключ владельца, запустить без Rust/Docker/Node/Python. Регистрация домена, аренда своего VPS и ручной проброс порта не обязательны. ARM64, графический мастер и установка службы — следующие пакеты, не обещанные возможности первого.

VPS/HTTPS/домен остаются поддерживаемым профилем, но не единственным. Разрешён домашний узел, в том числе дома в РФ; прежние требования к выбору зарубежного VPS/скрытию IP не применяются к добровольно выбранному домашнему профилю. Это не оценка правовых рисков и не обещание обхода блокировок. Адрес провайдера виден прямому собеседнику и сетевым посредникам; ASN/география/uptime не маскируются.

## 2. Две роли, не смешивать с HA

1. **Узел сообщений** — sm-relay, очереди шифротекста в RAM, FIFO/ACK/TTL/admission и авторизация.
2. **Транспортный ретранслятор** — добровольный доступный вход, который пересылает ограниченный защищённый поток между клиентом и домашним узлом. Он не владелец очереди и не реплика сообщений.

Целевой путь: прямое аутентифицированное соединение → попытка NAT traversal → ретрансляция. Реализацию начинаем с надёжного явно настроенного ретранслятора, затем добавляем прямой путь/обход NAT. Не объявлять hole punching гарантией. Общедоступный посредник нужен для запасного пути при несовместимых NAT; если нет ни прямой связности, ни доступного посредника/транспортной сети, гарантировать связь нельзя. «Без VPS каждому» не означает «без доступной инфраструктуры вообще».

Никаких скрытых публичных STUN/каталогов/туннельных SaaS по умолчанию. Список посредников задаёт владелец. Нет полного mesh всех участников: конечные списки, явные маршруты, лимиты каналов/буферов/попыток. Перегрузка/недоступность возвращают ограниченный отказ, не бесконечную очередь.

## 3. Доверие и транспортный контракт — следующий отдельный проект

Идентичность узла привязать к проверенному открытому ключу, не к текущему IP/домену. Подписанное приглашение должно задавать ключ, версию, способы связи, bootstrap-адреса, срок/полномочия. Смена IP требует аутентифицированного обновления адресов, replay protection, определения источника свежести и восстановления при недоступности bootstrap. Эти поля ещё не специфицированы; существующую SMN1/node body v2 не расширять молча.

Защищённый поток заканчивается на домашнем узле. Посредник не получает доступ к relay-командам/queue ID, но видит сетевые адреса, объём/время трафика и может отказать/обрывать соединения. Использовать проверенный криптотранспорт через обычный ADR/supply-chain, без своей криптографии, skip-verify или доверия любому сертификату. Выбор TLS/другой библиотеки и зависимостей ещё не принят. Первый пакет оставляет loopback-only ядро, без открытия plaintext relay в интернет или LAN.

Для будущего ретранслятора обязательны взаимная авторизация ролей, защита от открытого прокси/SSRF (никаких произвольных target host:port), лимит сессий/буферов/времени, конечный reconnect с backoff/jitter, изоляция медленного читателя, отмена при разрыве, ротация посредника и ключей, отсутствие логов/телеметрии. Возврат к прямому пути не отключает проверку ключа. NAT traversal меняет прежние сетевые ограничения только в явно согласованном новом транспорте, не в старом Android-клиенте.

## 4. Приватность и эксплуатация

RAM-only и полный запрет телеметрии сохраняются у узла и нашего транспортного компонента. Запрещены журналы запросов, метрики/гистограммы/счётчики использования, автоматическая отправка диагностики. Проверка локальной конфигурации по явной команде не выполняет сетевые пробы и не хранит историю.

Постоянны только разрешённые настройки и служебные ключи; сообщения/очереди не записываются. Корневой закрытый ключ владельца никогда не устанавливается на обслуживающий узел; init его не генерирует. Конфигурация содержит только открытые roots и путь к отдельному guest key. Подмена локальной конфигурации меняет доверие: права доступа — зона администратора.

Запуск бинарника не является доказательством OS-level RAM-only. Для Windows отдельно проверить pagefile/hibernation/crash dumps и покрытие всех буферов, для Linux — swap/core/лимиты. Не отключать системные настройки пользователя автоматически. До этого Windows-комплект только испытательный, не соответствующий полностью privacy deployment acceptance. Требование не ослаблено.

Сон/выключение ПК останавливают доставку, потеря RAM уничтожает очереди; повторное создание/повторы — клиент. Несколько посредников не дают HA очередей. Репликация 2/3 по ADR-153 остаётся отдельным незавершённым компонентом. Клиент не должен скрывать отказ или сообщать успешную доставку без нужных подтверждений.

## 5. Пакеты и приёмка

| Этап | Объём | Критерий готовности |
|---|---|---|
| H1 | Native Windows/Linux x64 сборки, versioned bounded config, init/check/start, roots без пересборки, legacy env запуск | Тесты обеих ОС, malformed/oversized/duplicate/unknown config, no-overwrite, fail-closed roots/limits, без секретов в stdout; архив, SHA256 и точный source SHA. Только test artifacts до релизной проверки/подписи. |
| H2 | Защищённый транспорт без обязательного домена и новый формат bootstrap/invite | Спецификация/совместимость, проверка ключа, replay/rotation, модифицированный клиент; без skip-verify. |
| H3 | Явно настроенный исходящий туннель через добровольный ретранслятор | Реальные CGNAT сети с обеих сторон, offline/reconnect/смена IP/медленный peer/исчерпание памяти; никакого открытого прокси и дисковой очереди. |
| H4 | Прямой путь/NAT traversal/несколько посредников | Матрица сетей/ограниченные попытки/отказ fallback, стабильность при смене сети; внешние синтетические замеры, без telemetry. |
| H5 | Завершённая эксплуатационная упаковка | OS RAM-only, graceful shutdown/autostart/uninstall/update/rollback, подпись релизов и инструкция без компилятора, испытания Windows/Linux и телефонов. |

Исходный план требует и бинарников, и H2/H3; завершение H1 не выдавать за домашний узел, уже доступный из интернета. GUI до реализации проходит UI-MOCKUP-FIRST. Пользовательскую машину/роутер/VPS в этих пакетах без отдельного запроса не изменять.

Состояние H1 и команды — `wiki/workflows/relay-home-deploy.md`; прежнее развёртывание — `wiki/workflows/relay-deploy.md`.
