# Требования владельца

Ответы владельца на вопросы по архитектуре. Источник — чат, 2026-10-09 (R-1…R-8 — раунд 1, R-9…R-13 — раунд 2, R-14…R-20 — раунд 3). Меняются только по слову владельца.

| # | Тема | Решение | Следствие для архитектуры |
|---|---|---|---|
| R-1 | Пользователи и устройства | Исходно 2–5 человек на Android; потолок пользователей узла снят решением 2026-10-14 (R-23), платформы клиента без изменений | Свой клиент только под Android; iOS не делаем. Распространение APK — см. `wiki/references/platforms.md` |
| R-2 | Сеть | Много мобильного интернета, в том числе в регионах с белыми списками; возможно — участники в разных регионах и за границей | Пути через белые списки нужны с первой версии; лестница транспортов — `wiki/architecture/overview.md` |
| R-3 | Связь без интернета | В будущем — Meshtastic / MeshCore / Reticulum | Транспортный слой с единым интерфейсом, mesh — отдельные модули позже. Факты — `wiki/references/mesh.md` |
| R-4 | Модель угроз | Сейчас — только чтобы связь работала при блокировках; позже, возможно, защита при изъятии телефона и незаметность приложения | В v1 без маскировки и пароля под принуждением, но формат хранилища не должен мешать добавить их позже |
| R-5 | Основа | Свой клиент (libsignal + OpenMLS), не форк | Форк SimpleX и готовые приложения отклонены |
| R-6 | Кто пишет код | Только ИИ-агенты | Обязательны: тесты, CI, статический анализ, независимая проверка криптографии и ключей. Факты о рисках — `wiki/references/ai-dev.md` |
| R-7 | Типы данных | v1 — только текст; в будущих релизах — всё вплоть до голосовых звонков | Формат сообщений и транспорт с запасом под вложения и потоковый голос; голос — только по быстрым каналам |
| R-8 | Диагностика | В приложении нужен тест, который показывает, что доступно прямо сейчас | Встроенная проверка транспортов и типов данных — `wiki/architecture/overview.md`, раздел «Диагностика» |
| R-9 | Установка APK | Основной путь — каждый участник один раз включает «расширенный режим» установки Android (ожидание 24 ч); запасной — установка через ADB с компьютера | Нужна пошаговая инструкция под оба пути; ADB не затронут верификацией разработчиков — `wiki/references/platforms.md` |
| R-10 | Устройства | Несколько устройств у участника (телефон + компьютер или второй телефон), история синхронизируется | Каждое устройство — отдельный получатель со своими ключами; в MLS — отдельный участник группы; нужен зашифрованный перенос истории на новое устройство (ADR-17). Компьютер — Windows (R-19) |
| R-11 | Первый mesh | Reticulum первым; у владельца есть LoRa-модуль Heltec V3 | Heltec LoRa32 v3 поддерживается прошивкой RNode — `wiki/references/mesh.md`; mesh-плагин Reticulum (ADR-18) |
| R-12 | Проверка кода ИИ | Только автоматика: тесты, CI, линтеры, фаззинг, ИИ-ревьюеры; лимит токенов и выбор моделей не ограничены | Конвейер проверки из нескольких слоёв и нескольких моделей разных разработчиков — `wiki/references/ai-security-review.md`, ADR-20 |
| R-13 | Охват диагностики | Тест проверяет только наши серверы и транспорты; телефоны группы обмениваются результатами по зашифрованным сообщениям | Нет обращений к сторонним сайтам; результаты — отдельный тип сообщения (ADR-14, ADR-19) |
| R-14 | Доступ к ИИ-моделям | Есть и закрытые (Claude, GPT, Gemini), и открытые (DeepSeek, GLM, Qwen) | Ансамбль ревьюеров из ADR-20 возможен целиком |
| R-15 | Бюджет на серверы | Исходно до $10 в месяц; с 2026-10-14 не ограничивает архитектуру/исследование пределов узла (R-23) | Допускаются другие конфигурации и несколько узлов; конкретное развёртывание и расходы выбираются отдельно |
| R-16 | Обновления | Приложение само проверяет наш сервер и сверяет подпись | Ключ подписи релизов хранится отдельно от сервера; сервер обновлений может совпадать с реле (ADR-21) |
| R-17 | Группы | Несколько групп | Отдельная группа MLS на каждую группу; с R-10 — все устройства участников в каждой группе |
| R-18 | Mesh-железо | 2 модуля Heltec V3, подключение к телефону по Bluetooth | Плагин Reticulum работает с RNode по BLE; известны проблемы сопряжения на Android 15/16 — `wiki/references/mesh.md` |
| R-19 | Компьютер | Второе устройство-компьютер — Windows | Клиент для Windows на общем ядре Rust (ADR-22); Windows-устройство — отдельный получатель по ADR-17 |
| R-20 | Добавление контактов | Оба способа: QR-код при встрече и ссылка-приглашение через другой канал | Ссылка — одноразовая и с ограниченным сроком; ключ, полученный по ссылке, помечается «не сверен», пока не сверен QR или кодом безопасности (ADR-23) |
| R-21 | Транспорт 0.0.2-alpha | Прямой HTTPS-API узла на своём домене; VLESS/Reality — в 0.0.3-alpha | ADR-84; идеи агента от 2026-10-11 приняты — ADR-84…87 |
| R-22 | Канал для ссылок-приглашений | В основном Telegram; код к ссылке — по выбору, для опасных каналов (2026-10-11) | ADR-133: код выключен по умолчанию, подсказка включать его для MAX и других каналов без сквозного шифрования |
| R-23 | Контракт и масштаб узла | Фиксируем внешний контракт, не реализацию; RAM-only и полный запрет телеметрии сохраняются. Число пользователей и ресурсы без заранее заданного потолка; квоты настраиваемые, несколько узлов допустимы (владелец, 2026-10-14) | ADR-152; `wiki/architecture/relay-contract.md`. Это требования, не уже реализованное масштабирование или новая версия wire |
