# Требования владельца

Ответы владельца на вопросы по архитектуре. Источник — чат, 2026-10-09. Меняются только по слову владельца.

| # | Тема | Решение | Следствие для архитектуры |
|---|---|---|---|
| R-1 | Пользователи и устройства | 2–5 человек, все на Android | Свой клиент только под Android; iOS не делаем. Распространение APK — см. `wiki/references/platforms.md` |
| R-2 | Сеть | Много мобильного интернета, в том числе в регионах с белыми списками; возможно — участники в разных регионах и за границей | Пути через белые списки нужны с первой версии; лестница транспортов — `wiki/architecture/overview.md` |
| R-3 | Связь без интернета | В будущем — Meshtastic / MeshCore / Reticulum | Транспортный слой с единым интерфейсом, mesh — отдельные модули позже. Факты — `wiki/references/mesh.md` |
| R-4 | Модель угроз | Сейчас — только чтобы связь работала при блокировках; позже, возможно, защита при изъятии телефона и незаметность приложения | В v1 без маскировки и пароля под принуждением, но формат хранилища не должен мешать добавить их позже |
| R-5 | Основа | Свой клиент (libsignal + OpenMLS), не форк | Форк SimpleX и готовые приложения отклонены |
| R-6 | Кто пишет код | Только ИИ-агенты | Обязательны: тесты, CI, статический анализ, независимая проверка криптографии и ключей. Факты о рисках — `wiki/references/ai-dev.md` |
| R-7 | Типы данных | v1 — только текст; в будущих релизах — всё вплоть до голосовых звонков | Формат сообщений и транспорт с запасом под вложения и потоковый голос; голос — только по быстрым каналам |
| R-8 | Диагностика | В приложении нужен тест, который показывает, что доступно прямо сейчас | Встроенная проверка транспортов и типов данных — `wiki/architecture/overview.md`, раздел «Диагностика» |
