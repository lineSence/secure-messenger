# Ядро `sm-core` (шаг 1 плана MVP)

Код: `crates/sm-core/src/`. Решения: ADR-1, ADR-12, ADR-13, ADR-14, ADR-24, ADR-40, ADR-49. Зависимость одна — `zeroize` (закреплена `=1.8.2`: последняя версия с цепочкой аудитов Mozilla и Bytecode Alliance в `cargo vet`, проверено 2026-10-09).

## Модули
| Модуль | Что делает |
|---|---|
| `wire` | Чтение враждебных данных: границы проверяются, память по длине из данных не выделяется. Текст — UTF-8 без NUL и без символов смены направления письма (U+061C, U+200E, U+200F, U+202A–U+202E, U+2066–U+2069) |
| `message` | Формат сообщения v1. `parse` — разбор без копирования (его проверяет Kani), `Message::decode` / `encode` — с копированием. Кодирование каноническое |
| `padding` | Выравнивание длины перед шифрованием: `0x80` + нули до степени двойки, от 64 байт до 128 КиБ |
| `keystore` | Хранилище ключей. Шифрует платформа через `KeyWrapper` (Android Keystore, Windows DPAPI); метка привязана к записи. Секрет в памяти обнуляется при удалении и не печатается |
| `transport` | Интерфейс транспортного плагина: `send`, `fetch`, `probe`; ошибки размечены для лестницы (`should_fall_back`). `Loopback` — образец и основа тестов |
| `delivery` | Доставка до подтверждения (ADR-40). `Outbox` хранит зашифрованный блоб до `Delivered` от получателя, повторяет с паузой 1 мин → ×2 → до 1 ч и после смены или перезагрузки узла без экспоненциальной паузы (`retry_all_now`, но не чаще раза в минуту после прошлой попытки: узел недоверенный); через 7 дней без подтверждения — «не доставлено» (`expire`); все сроки — по монотонным часам, которые передаёт клиент (Android `SystemClock.elapsedRealtime()`), а не по времени UNIX: перевод стеночных часов не замораживает и не старит очередь; монотонные часы идут назад только после перезагрузки — это новый отсчёт. Отметки времени одной загрузки не сравниваются с часами другой загрузки или устройства: после перезагрузки устройства (сменился номер загрузки: Android `Settings.Global.BOOT_COUNT`) клиент вызывает `rebase` один раз при восстановлении очереди, а не при каждом перезапуске процесса: возраст и попытки сохраняются, отметки — на текущее время, оставшаяся пауза до повтора сохраняется (не больше 1 ч, после попытки — не меньше 1 мин). `Seen` у получателя отсекает дубли по (ящик собеседника, id), окно своё у каждого собеседника (10 000 id), чтобы один не вытеснил чужие, подтверждение отправляется на каждый приход, в том числе на дубль. Пределы очереди — как у очереди узла: 1000 сообщений, 32 МиБ. Сохранение между запусками — `delivery::store` (ниже) |
| `delivery::store` | Снимки `Outbox` и `Seen` для хранения между запусками (формат — ниже). Снимок очереди хранит номер загрузки устройства: `Outbox::restore` сам вызывает `rebase`, если номер сменился, и не трогает отметки при перезапуске процесса в той же загрузке. Разбор: границы проверяются, длины и числа из файла сверяются с пределами и с остатком данных до чтения, память — только по фактическим данным; запись каноническая (записи по возрастанию ключа, без повторов) — проверяет фаззер `store_restore`. Пределы очереди уменьшились — отказ `OverLimit` (клиент решает, что делать), ёмкость окон уменьшилась — остаются самые новые ID. Шифрование снимка на диске — платформа (Android Keystore), не ядро |
| `chunk` | Нарезка кадра «ящик 32 байта + блоб» на части ≤ 512 байт (значение атрибута GATT) для Bluetooth LE и сборка (ADR-49). Часть: `[версия 1][передача u16][номер u16][всего u16][данные]`. Сборщик — один на соединение, принимает части только по порядку: память растёт по мере прихода данных, не по числам из заголовка; и длина, и выделенная память незаконченного кадра — не больше предела (32 + блоб узла); пропуск, повтор, чужая передача или превышение предела сбрасывают незаконченный кадр; часть 0 всегда начинает новый. Проверяют тесты, фаззер `chunk_reassemble` и Kani `chunk_push_total` |
| `relay` | Протокол узла-реле (кадры запроса и ответа, пределы до выделения памяти) и плагин `RelayTcp` — `wiki/architecture/relay.md` |

## Формат сообщения v1
`[версия u8 = 1][тип u16 BE][id 16 байт][время отправки, мс, u64 BE][тело]`

| Тип | Тело | Предел |
|---|---|---|
| 1 текст | UTF-8 | 16 КиБ |
| 2 ответ | id исходного (16) + текст | 16 КиБ |
| 3 реакция | id исходного (16) + эмодзи; пусто — снять | 32 байта |
| 4 отчёт диагностики | байты (формат — шаг 6) | 8 КиБ |
| 5 подтверждение доставки (ADR-40) | ровно id доставленного (16) | 16 байт |
| другой | хранится как есть, интерфейс предлагает обновиться | 64 КиБ |

Другая версия формата не разбирается. Порядок обработки входящего: расшифровка (libsignal/OpenMLS) → `padding::unpad` → `message::parse`.

## Снимки очереди и окон
Очередь: `[версия u8 = 1][загрузка u64][число u32]`, записи по возрастанию ключа: `[ящик 32][id 16][порядок u64][возраст u64][учтено u64][след. попытка u64][была попытка u8 0/1][последняя попытка u64, 0 — не было][попыток u32][блоб: u32 длина + байты, не пустой]`.
Окна: `[версия u8 = 1][собеседников u32]`, окна по возрастанию ящика: `[ящик 32][число u32, не 0][id по 16 байт, от старого к новому, без повторов]`.

## Запись хранилища ключей
`[версия u8 = 1][метка: u16 длина + байты][обёрнутый секрет: u16 длина + байты]`. Метка — `[a-z0-9._-]`, 1–64 символа, первый символ `[a-z0-9]`, без `..` и без `.` в конце, не зарезервированное имя Windows (`con`, `prn`, `aux`, `nul`, `com0`–`com9`, `lpt0`–`lpt9`, в том числе с расширением, например `nul.x`): метка может стать именем файла на любой ОС.

## Проверки
- Запрет криптопримитивов (ADR-1): `cargo deny check bans` по реальному графу зависимостей (`deny.toml`, `[bans].deny`) — главная проверка; semgrep `sm-no-crypto-dependency` и `sm-no-own-crypto` — быстрая подсказка с тем же списком крейтов; `sm-no-toml-escapes` запрещает в `Cargo.toml` `\u`-экранирование и тройные кавычки.
- Юнит-тесты: `cargo test`.
- Фаззинг: `fuzz/fuzz_targets/message_decode.rs` (сообщение + выравнивание, каноничность), `keystore_record.rs`, `relay_frame.rs` (кадры узла, каноничность), `chunk_reassemble.rs`, `store_restore.rs` (снимки очереди и окон, каноничность).
- Kani (`cargo kani -p sm-core`, `crates/sm-core/src/proofs.rs`): разбор сообщения до 32 байт, проверка текста, чтение полей, снятие выравнивания, разбор записи ключа, заголовки кадров узла — без паник на любом входе.
