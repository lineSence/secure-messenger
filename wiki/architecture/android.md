# Android-клиент

Код: `android/` (приложение), `crates/sm-ffi/` (обёртка ядра), `tools/uniffi-bindgen/` (генератор привязок), `scripts/build-android-core.sh` (сборка ядра). Решения: ADR-45, ADR-46, ADR-48, ADR-49; интерфейс — `ux.md` (UX-1…24, макет v6).

## Устройство
| Слой | Что | Где |
|---|---|---|
| Интерфейс | Kotlin + Jetpack Compose, Material 3; тема по системе | `android/app/src/main/java/dev/sm/messenger/` |
| Привязки | Kotlin-код UniFFI, генерируется при сборке, в git не хранится; вызовы через JNA | `android/app/build/generated/uniffi/` |
| Ядро | `libsm_ffi.so` (`sm-ffi` → `sm-core`, `sm-signal`), только `arm64-v8a`; `core_self_check()` проверяет и формат сообщения, и круг libsignal | `android/app/build/generated/jniLibs/` |

- `sm-ffi` — тонкая обёртка: наружу только типы UniFFI, логика — в `sm-core`. Те же строгие линты рабочего пространства (ADR-15, ADR-20), `unsafe` запрещён (код FFI генерирует макрос UniFFI).
- Генератор привязок той же версии UniFFI (`=0.32.2`) — отдельный workspace: инструмент сборки не попадает в граф зависимостей приложения; в CI его граф проверяют `cargo deny` (bans) и `cargo audit`, как `fuzz/`.
- Минимальная версия — Android 12 (API 31); компилируется с API 37 (этого требует Compose BOM 2026.09), `targetSdk` — 36: поведение API 37 включим отдельно после проверки BLE.
- Зависимости UniFFI в `cargo vet` — по ADR-50 (импорт аудитов, доверие издателям, исключения); лицензия UniFFI MPL-2.0 добавлена в `deny.toml`.
- Резервное копирование выключено (`allowBackup=false`, `data_extraction_rules`): ключи и переписка не уходят в облако и на другое устройство.

## Сборка
```
export ANDROID_NDK_HOME=<NDK r28>
rustup target add aarch64-linux-android
bash scripts/build-android-core.sh        # .so + привязки Kotlin
cd android && gradle assembleDebug        # Gradle 9.8.1
```
- Уязвимые транзитивные зависимости инструментов сборки (AGP: Bouncy Castle, commons-lang3, httpclient, jose4j, jdom2, Kotlin Gradle Plugin 2.2.10) закреплены на исправленных версиях в `android/settings.gradle.kts` — их находит OSV-Scanner по `verification-metadata.xml`; в APK они не попадают.
- Gradle-wrapper в репозитории нет (бинарники не храним): CI скачивает дистрибутив Gradle 9.8.1 и сверяет его sha256 с закреплённой в `.github/workflows/ci.yml` (`dce76f55…c01f`, опубликована на services.gradle.org, проверено 2026-10-10); `gradle/actions/setup-gradle` — только кэш.
- Зависимости Gradle проверяются в `verification-metadata.xml`: подписи PGP (`verify-signatures=true`, 35 ключей издателей в `android/gradle/verification-keyring.keys`, текстовый формат) и sha256. Ключи и суммы записаны при первой сборке (доверие при первом получении, 2026-10-10); у артефактов без подписи или с ключом, которого нет на серверах ключей (13 ключей в `ignored-keys`), проверяется только sha256. Обновление: `gradle --write-verification-metadata pgp,sha256 --export-keys assembleDebug`, затем удалить `verification-keyring.gpg` и проверить разницу в PR. Генератор пропускает часть артефактов, которые разрешаются во время выполнения задач (отдельные конфигурации): их sha256 дописаны вручную из кэша Gradle после сверки SHA-1 с Maven Central (2026-10-10, ZXing и CameraX: `error_prone_annotations` 2.18.0/2.28.0, `error_prone_parent` 2.28.0, `j2objc-annotations` 2.8, `kotlin-bom` 1.8.0).
- Самопроверка ядра при запуске: если библиотека ядра не загрузилась или `coreSelfCheck()` не прошла, приложение показывает только экран ошибки и дальше не работает (отказ в закрытую сторону).
- CI (задача `android`, ADR-48): APK собирается только в PR, где изменены `android/`, `crates/`, `Cargo.*`, генератор или сборка; иначе задача успешно завершается без сборки (пропуск задачи в PR роняет `ci-ok`). APK — артефакт прогона `sm-debug-apk` на 14 дней.
- Название и версия (ADR-77, ADR-78, #39): в лаунчере — «Uncensored»; `versionName` — единственный источник `appVersion` в `android/app/build.gradle.kts`, сейчас `0.0.1-alpha` (`versionCode` 1); имя APK — `uncensored-<версия>-<тип>.apk` (`base.archivesName`), например `uncensored-0.0.1-alpha-debug.apk`; APK релиза — `uncensored-<версия>.apk`. `applicationId` — `app.uncensored` (#48, ADR-77); `namespace` (пакет кода) прежний — `dev.sm.messenger`.
- Подпись релиза (ADR-76, #41): `.github/workflows/release.yml` по тегу `v*`, окружение `release` с одобрением владельца; тег должен совпадать с `v<versionName>`; `assembleRelease lintRelease` без кэша Gradle → `apksigner` (v2 + v3) → `verify --print-certs`; SHA-256 APK и сертификата — в сводке задачи и в черновике релиза на GitHub (публикует владелец). Секреты: `RELEASE_KEYSTORE_B64`, `RELEASE_KEYSTORE_PASSWORD`, `RELEASE_KEY_ALIAS`, `RELEASE_KEY_PASSWORD`. Проверено на теге `v0.0.1-alpha` (2026-10-11). Новые build-tools пишут в `apksigner verify` строку `V3.0 Signer: certificate SHA-256 digest:`, а не `Signer #1 …` — разбор понимает обе (#52).
- Сеть только TLS (ADR-72, #40): `res/xml/network_security_config.xml` — `cleartextTrafficPermitted=false` для всех доменов, доверие только системным CA (пользовательские сертификаты, в т.ч. Russian Trusted CA, установленный вручную, не доверены); в манифесте `usesCleartextTraffic=false`. Сети в приложении пока нет — конфиг заранее, к 0.0.2.

## Bluetooth рядом (ADR-49)
Код: `android/app/src/main/java/dev/sm/messenger/ble/`. Экран — по макету `ui-v6.html` (UX-23, UX-24): вкладка «Связь» нижней панели, переключатель, системное окно разрешений, баннер «Настройки» при отказе, список «Телефоны рядом» с «Подключить», «вне досягаемости — сообщения ждут в очереди».

| Что | Как |
|---|---|
| Разрешения | `BLUETOOTH_SCAN` (`neverForLocation` — местоположение не запрашивается), `BLUETOOTH_CONNECT`, `BLUETOOTH_ADVERTISE`; запрос — при первом включении |
| Видимость (ADR-61) | объявление BLE только с UUID-меткой, без имени устройства и мощности; метка меняется каждые 15 минут (`Beacon`, ядро `ble_add_nearby_token`), поиск — фильтр по меткам эпох t−1, t, t+1; на сервере GATT — сервис текущей и прошлой эпохи, UUID характеристики «входящие» выводится из UUID сервиса. Метки — по ключам маяка (`ContactBeacon`, ядро `ble_contact_token`): свою объявляем по своему ключу, ищем по ключам контактов (эпохи t−1..t+1, таблица меток пересчитывается раз в эпоху); в списке «Телефоны рядом» — имя контакта. Ключи читаются из `ContactBook` при включении и после добавления контакта; не прочитались — Bluetooth не включается. Контактов нет — поиск не запускается, объявляется только своя метка. Общая метка `sm-add/v1` — только у `PairLink` на экране добавления |
| Сервер GATT | у каждого телефона; одна характеристика «входящие» — только запись с подтверждением; длинные (prepared) записи отклоняются; один `ChunkReassembler` из ядра на соединение (удаляется при разрыве), не больше 4 соседей одновременно |
| Клиент GATT | по «Подключить»: MTU 517 → часть = `MTU − 3` (≤ 512), запись частей строго по одной (следующая — после ответа); сбой — кадр заново с части 0, до 3 попыток; разрыв — кадр остаётся в очереди (≤ 64) и уходит после переподключения, переподключение — само, когда телефон снова виден |
| Ядро | `sm-ffi` экспортирует `chunk_split`, `ChunkReassembler`, `encode_frame`, `parse_frame`, `chunk_max_len` — обёртки над `sm_core::chunk`; байты в ядро — `&[u8]` без копирования (в Kotlin — прямой `ByteBuffer`) |
| Доставка (ADR-40) | увидели метку контакта, которому есть что отправить (`ChatHub.waiting`), — `BleHub` подключается клиентом GATT (к одному телефону за раз; к тому же контакту после разрыва — снова, адрес мог смениться); после подключения неотправленные кадры прошлого соединения выбрасываются (`clearQueue`), `ChatHub.collect` шифрует заново подтверждения и всё из очереди (`retry_peer_now`), пока подключены — раз в 30 с досылает то, чему подошёл срок. Поле ящика в кадре — нули: узла нет. Принять кадр (сервер GATT) можно от любого контакта одновременно |
| Повторное подключение (ADR-69 п.3, #43) | после разрыва или ошибки GATT (в т.ч. 133) клиент GATT закрыт (`close()`), автоподключение ждёт паузу 1 с · 2^(n−1), не больше 60 с, разброс ±20 %; сброс при подключении и выключении связи; ручное подключение из списка паузу не ждёт. На телефонах не проверено |
| После перезагрузки (ADR-69 п.2, #44) | `BootReceiver` на `BOOT_COMPLETED` и `MY_PACKAGE_REPLACED` (защищённые события) запускает `BleService`, если пользователь оставил связь включённой (`BleHub.wanted`, `SharedPreferences` в CE; сбрасывает только выключатель на экране «Связь»); ядро, ключи, разрешения и Bluetooth проверяет служба, при отказе останавливается. Событие приходит после первой разблокировки. На телефонах не проверено |
| Связь в фоне (ADR-59, UX-18) | состояние и `BleLink` — в `BleHub`, один на процесс (не в `ViewModel`): закрытие экрана связь не рвёт. Пока связь включена, работает `BleService` — служба переднего плана типа `connectedDevice` с уведомлением «Соединение активно» (канал «Соединение», тихий; текст — состояние связи; нажатие открывает приложение); выключение — служба останавливается. Запуск из фона Android запрещает — тогда связь работает, пока открыто приложение (подсказка на экране). Система убила процесс — перезапускает службу (`START_STICKY`), связь включается снова только при исправном ядре и выданных разрешениях. Разрешение «Уведомления» (API 33+) объявлено, запрос — на экране первого запуска; без него служба работает, но уведомление скрыто |

Ограничения: на телефонах не проверено; клиентом — один телефон за раз (при нескольких контактах рядом очередь второго ждёт, пока первому нечего слать).

## Узел по HTTPS (п.9 плана 0.0.2-alpha; ADR-84, ADR-85, ADR-86, ADR-93)
Пакет `relay/`. Подключение к почте — п.11, адреса узла из подписанной записи — п.10.

| Что | Как |
|---|---|
| Кадры | собирает и разбирает ядро: `relay_request`, `relay_reply_parse`, `relay_reply_max` (`sm-ffi::relay` поверх `sm_core::relay`); тело запроса и ответа — ровно один кадр |
| Клиент (`HttpsRelay`) | `HttpsURLConnection` (Conscrypt; только HTTP/1.1 — так устроен системный клиент), `POST` на секретный путь из записи узла; не `200` или чужое тело — `Blocked`; тело ответа длиннее предела не дочитывается |
| Пин (`Pinning.kt`) | системная проверка цепочки и имени + SHA-256 ключа (SPKI) листа из записи узла (ADR-72); в коде, не в `network_security_config` (ADR-90) |
| Соединения | пул keep-alive `HttpsURLConnection`: обычно одно, второе — пока первое занято `WAIT`; без `VpnService` и локальных портов |
| Домены (`DomainRotation`) | по порядку со случайного места; блокировка или недоступность — сразу следующий, тайм-аут — если 120 с не было ответа (ADR-86) |
| Сроки (`RelaySchedule`) | мобильная сеть — опрос 2→15 мин, ±25 %; повтор после ошибки — 5 с…5 мин, удвоение, джиттер; канал по Wi-Fi живёт 5–15 мин, `renewChannel()` — новая фабрика сокетов = новое TLS-соединение, старое закрывает `keepalive_timeout` nginx (ADR-93) |
| Тесты | `RelayPolicyTest` (JVM): перебор доменов, сроки, пин, проверка записи узла |

## Хранилище клиента (ADR-56)
Код: `android/app/src/main/java/dev/sm/messenger/store/`; ядро — `sm-ffi` (`OutboxQueue`, `SeenWindow`) над `sm_core::delivery` и `delivery::store`.

| Что | Как |
|---|---|
| Ключ | `sm.store` — AES-256-GCM в Android Keystore (TEE), не извлекается; без требования разблокировки и подтверждения пользователя |
| Файлы | `noBackupFilesDir/sm/outbox.v1` и `seen.v1` (хранилище CE), запись через `AtomicFile`; формат `[1][IV 12][шифротекст + тег]`, связанные данные `sm/v1/` + имя файла |
| Отказ | файл не расшифровался или снимок не разобрался — начинаем с пустой очереди и окна; при сломанном замке в ядре (`Broken`) прежний файл не перезаписывается |
| Когда пишем | не позже 1 с после изменения (`changed()`) и в `onStop`, в потоке `sm-store` (главный поток не ждёт) |
| Загрузка устройства | `Settings.Global.BOOT_COUNT` → `OutboxQueue.restore` переносит отметки при смене; не прочитался — перенос при каждом запуске |

## Ключи устройства и первый запуск (пункт 4, ADR-56, UX-17)
Код: `keys/DeviceKeys.kt`, `onboarding/`.

| Что | Как |
|---|---|
| Ключ Keystore | `sm.keys` — AES-256-GCM, сначала в StrongBox, при `StrongBoxUnavailableException` — в TEE; связанные данные `sm/v1/key/` + метка; открытый секрет после шифрования обнуляется |
| Записи | `noBackupFilesDir/sm/keys/<метка>` через `AtomicFile`; метку проверяет ядро |
| Ключ личности | создаёт и хранит ядро (`DeviceIdentity`, `signal.md`); Kotlin видит только открытый ключ — на экране 16 байт в hex группами по 4 |
| Запуск | ядро исправно → `DeviceKeys.load()`: нет ключа — первый запуск; ключ не открывается — экран «Ключ шифрования не открывается», новый молча не создаётся (контакты увидели бы чужой ключ) |
| Первый запуск | по макету: приветствие → имя (до 32 знаков, `SharedPreferences` `sm.profile`) → создание ключей (не в главном потоке) с предупреждением «Копии на сервере нет» → разрешения «Уведомления» (API 33+) и «Работа в фоне» (окно `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`), можно пропустить. Нет шагов «Уже пользуюсь на другом устройстве» (`0.3.0`) и «Проверка связи» (узлов нет); первый контакт — пункт 5. Третий пункт приветствия — «Работает без интернета · по Bluetooth» вместо LoRa, которой в alpha нет |
| Закрыли посреди первого запуска | ключ уже есть — второй не создаётся, шаги продолжаются с ним |

## База и контакты (пункт 5, ADR-63)
Код: `store/SecureDb.kt`, `contacts/ContactBook.kt`.

| Что | Как |
|---|---|
| База | SQLite из Android (`SQLiteOpenHelper`), файл `sm.db` в каталоге приложения, версия схемы 2 (1 → 2 добавляет `messages`); неизвестная версия — отказ, не пересоздание |
| Строки Signal (`kv`) | `tbl` (имя таблицы ядра), `k`, `v`; `k` — HMAC-SHA256 ключом Keystore `sm.index` от «таблица ‖ 0 ‖ id» (id ядра содержат ключ личности контакта — по файлу их не связать с людьми); `v` — AES-256-GCM ключом `sm.store`, связанные данные `sm/v1/db/kv/` + таблица + `k`. Интерфейс для ядра — `SignalKv` (`PlatformKv`): любая ошибка Keystore, SQLite или расшифровки — `SignalFfiException.Store`, операция Signal отменяется (ADR-63 п.5) |
| Контакты (`contacts`) | открыто — внутренний `id` и время добавления; остальное (адрес = ключ личности в hex, имя, ключ личности, ключ маяка, «сверен») — JSON, зашифрованный `sm.store` со связанными данными `sm/v1/db/contacts/` + id. Строка, которая не расшифровалась, в список не попадает (счётчик на стартовом экране) и молча не перезаписывается. Повторное добавление того же ключа обновляет имя и ключ маяка, «сверен» не снимается |
| Свой ключ маяка | строка `kv` таблицы `self`, создаётся ядром (`beacon_key_new`) при первом добавлении контакта; смена при удалении контакта — позже (удаления ещё нет) |
| История (`messages`) | открыто — `id` строки, внутренний `id` контакта, время на этом телефоне и `mid` — HMAC `sm.index` от «направление ‖ адрес контакта ‖ 0 ‖ id сообщения» (уникальный: дубль не записывается, подтверждение находит строку; своё id не совпадёт с чужим); текст, направление, время отправителя и статус — в зашифрованной строке (`db/messages/<id>`) |
| Прочитано | `kv` таблицы `chat_read`: адрес контакта → последний прочитанный `id` строки; непрочитанные — входящие новее него |

## Добавление контакта (пункт 5, ADR-62, UX-25)
Код: `contacts/` — `Pairing.kt` (шаги), `PairLink.kt` (Bluetooth), `QrCode.kt` (ZXing, CameraX), `AddContactScreen.kt` (экран по макету `ui-v7.html`). Протокол и криптография — в ядре (`signal.md`: `SignalSessions`, `PairFrame`).

| Что | Как |
|---|---|
| Вкладки | «Мой QR», «Сканировать», «Рядом», «Ссылка» (ссылка — в `0.0.2`, на вкладке так и написано); подсказка на вкладках QR — «телефоны обменяются ключами по Bluetooth — держите их рядом» |
| Мой QR | QR (`SM1:` + HEX, ZXing, коррекция M) со своим ключом личности и одноразовым секретом; QR меняется каждые 5 минут (ADR-62: не дольше 10), секрет забывается при закрытии экрана. Телефон объявляет метку секрета и ждёт `Card` с доказательством; неверное доказательство — отказ без сохранения; одно добавление на один QR |
| Сканировать | CameraX (Preview + ImageAnalysis, яркость кадра → ZXing `QRCodeReader`), разрешение «Камера» — только на этой вкладке; чужой или свой QR — подсказка, сканирование продолжается. Ищет метки секрета на эпохи t−1..t+1, шлёт `Card` с доказательством; первое сообщение принимается, только если ключ отправителя — из QR. Не нашли телефон за 60 с — «Не получилось, ничего не сохранено» |
| Рядом | по «Искать рядом» (разрешение «Устройства поблизости» — системным окном): общая метка `sm-add/v1`, телефоны обмениваются `Intro` с именем и показывают список; «Добавить» → `Card` без доказательства → на втором телефоне «Добавить …?» → `Start` → на первом тоже «Добавить …?» → `Reply`; оба — «не сверен». Отказ или разрыв — «Не получилось, ничего не сохранено» (начатая сессия удаляется). Поиск — не дольше 10 минут |
| Bluetooth (`PairLink`) | отдельно от `BleLink`, только пока открыт экран: сервис GATT с UUID = метка, характеристика «труба» (UUID из метки): клиент пишет с подтверждением, сервер отвечает индикациями (дескриптор 0x2902) по тому же соединению — запрос и ответ без сопоставления случайных адресов Android. Части — `chunk_split`/`ChunkReassembler` ядра, строго по одной; не больше 6 соединений каждого вида и 8 кадров в очереди. Метка не меняется, пока экран открыт |
| Сохранение | контакт пишется только после того, как ядро приняло ключи (сканировавший — после проверки ключа из QR, показавший — после расшифровки ответа); Keystore, libsignal и SQLite — не в главном потоке |

Ограничения: на телефонах ещё не проверено; если ответ `Reply` не дошёл, у сканировавшего контакт есть, а у показавшего — нет (добавить заново); пока включён тестовый «Bluetooth рядом», его кадры могут приходить на экран «Рядом» — они не разбираются как кадры добавления и отбрасываются. Фильтров поиска — по три на контакт; при десятках контактов телефон может не принять столько аппаратных фильтров (не проверено).

|---|---|
| Экраны | нижняя панель «Чаты · Связь · Настройки» (UX-1). «Чаты»: полоса связи (UX-28: «Связь есть» / «Подключение…» / «Нет сети», новое состояние — если держится ≥ 2 с; нажатие — «Связь»), строки с аватаром, меткой «не сверен», последним сообщением, временем, значком «доставлено» и числом непрочитанных; пусто — UX-22; кнопка «Новый контакт».
