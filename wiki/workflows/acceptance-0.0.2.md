# Приёмка `0.0.2-alpha` на двух телефонах

Статус: **черновик чек-листа** (2026-10-17, `5ce368c`). Состав релиза — `wiki/workflows/releases.md`; стенд с одним телефоном — `wiki/workflows/test-stand.md`.

## Как пользоваться

- **P0** — блокер релиза: без зелёного пункта релиз не выпускается.
- **P1** — обязательна; известный дефект допустим только с записью в `releases/v0.0.2-alpha.md` и воспроизведением.
- **P2** — по возможности, не блокирует.
- Колонка «Стенд»: `2T` — два телефона (основной), `L1`/`L2` — см. `test-stand.md`; `L0` — только узел и один телефон.
- Результат — «прошло / не прошло / не проверено» и ссылка на debug-журнал или снимок экрана. Без этого пункт не закрыт.

## 4. Известные дефекты — целевая проверка

Проверить, что не воспроизводятся; при воспроизведении — дефект в `releases/v0.0.2-alpha.md` с шагами.

| ID | Что проверяем | Признак дефекта |
|---|---|---|
| E-01 | BLE-объявление контакта без рабочего GATT не блокирует отправку через узел | Сообщение висит «в очереди», хотя узел доступен |
| E-02 | Контакт после QR получает адрес почты без BLE-обмена | После QR и недоступного BLE сообщения через узел не уходят |
| E-03 | «Связь есть» и «Bluetooth» в пузыре не врут без подтверждённой отправки | Подпись есть, доставки нет |
| E-04 | Ссылка с телефона на мобильной сети завершается | Открытие ссылки не доходит до карточки/контакта |
| E-05 | Экран «Связь» не показывает `Idle` как «работает» без очередей | «Работает», хотя очередь не создана |

## 5. Критерии выхода

- Все P0 зелёные на двух телефонах в разных сетях (Wi-Fi и мобильная минимум двух операторов).
- P1 закрыты или записаны в `releases/v0.0.2-alpha.md` с воспроизведением и оценкой.
- Ни одного открытого critical/high после ИИ-ревью релиза (ADR-58).
- SHA кандидата совпадает с SHA проверенной сборки; APK подписан ключом владельца (ADR-76).
- Debug-журнал и снимки экрана приложены к отчёту приёмки.
