# План релизов

Решения — ADR-57 и ADR-59 (приняты владельцем 2026-10-10). Порядок ревью релиза — ADR-58 (принято). Шаги MVP, на которые опирается план, — `wiki/workflows/mvp.md`.

Правила для всех релизов:
- Между релизами — только проверки PR (`ci-ok`): тесты, clippy, cargo-deny/audit/vet, OSV, Semgrep, фаззинг, Kani, сборка APK. ИИ-ревью в PR нет (ADR-53).
- Тестовые debug-APK (артефакт `sm-debug-apk`) — для проверки владельцем на своих телефонах; людям — только сборка релиза.
- Релиз = тег `vX.Y.Z` после ИИ-ревью без открытых critical/high. Интерфейс новых экранов — сначала макет и согласие владельца ([UI-MOCKUP-FIRST]).

## 0.0.1-alpha — «Bluetooth рядом»
Рабочее Android-приложение: два телефона рядом без интернета добавляют друг друга и переписываются по Bluetooth LE с шифрованием Signal, в том числе при выключенном экране. Получают владелец и ещё один человек; срок — как можно скорее (ADR-59). **До этого релиза ИИ-ревью не проводится** (ADR-57); ревью релиза — первое, по всему коду.

## 0.0.2-alpha — «Интернет через свой узел»
Когда контакты не рядом, сообщения идут через свой зарубежный узел `sm-relay` по прямому HTTPS на своём домене (ADR-84, R-21); Bluetooth рядом работает как в 0.0.1-alpha. Новый контакт можно добавить по одноразовой ссылке — он «не сверен» до сверки кода. Получают те же двое. Шаги MVP 2 и 3; шаг 4 (VLESS + XHTTP + Reality) — в 0.0.3-alpha. ИИ-ревью — по diff от `v0.0.1-alpha` (ADR-58). План — 2026-10-11, обновлён в тот же день под ADR-84…87 (приняты) и отклонённый ADR-80; ADR-81…83 и ADR-90 приняты владельцем в тот же день.
