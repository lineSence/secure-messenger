# План MVP

Порядок шагов. Каждый шаг закрывается проверкой из колонки «Готово, когда». Все решения ADR приняты владельцем 2026-10-09 — `wiki/architecture/decisions.md`.

| # | Шаг | ADR | Готово, когда |
|---|---|---|---|
| 0 | Конвейер проверки в этом же репозитории (ADR-25): rustfmt, clippy, cargo-deny/audit/vet, OSV-Scanner, Semgrep (CodeQL недоступен — ADR-26), ИИ-ревью 2+ моделями, заготовка фаззинга; описание — `wiki/workflows/ci.md` | ADR-15, ADR-20, ADR-25 | PR с намеренно внесённой уязвимостью блокируется конвейером. **Проверено 2026-10-09:** PR #2 (выход за границы среза в `frame.rs`) заблокирован задачами rust, semgrep, fuzz. Шаг закроется слиянием PR #1 при зелёном `ci-ok` (нужен секрет `DAHL_API_KEY` или 2 вердикта ИИ-ревью из чата) |
| 1 | Ядро на Rust: формат сообщения с типом и версией, хранилище ключей, интерфейс транспортных плагинов | ADR-1, ADR-12, ADR-14 | тесты и фаззинг разбора формата зелёные; Kani — для разбора формата |
| 2 | Один зарубежный узел: очереди зашифрованных блобов в RAM, TTL, без логов | ADR-8, ADR-9 | два клиента обмениваются блобами; рестарт стирает всё; расход ≤ $10/мес |
| 3 | Android-клиент + libsignal 1:1; идентификатор — ключ; контакт по QR и одноразовой ссылке | ADR-2, ADR-6, ADR-10, ADR-23 | сообщение 1:1 доходит; контакт по ссылке помечен «не сверен» до сверки; смена ключа блокирует отправку |
| 4 | Транспорт-плагин VLESS + XHTTP + Reality | ADR-7 | работает через мобильных операторов минимум в двух регионах |
| 5 | Лестница транспортов, автопереключение, пути при белых списках без своего сервера | ADR-7, ADR-9 | при блокировке основного сообщение уходит запасным без действий пользователя; доставка при включённых белых списках |
| 6 | Диагностика: проба наших узлов и транспортов, отчёт группе по E2E | ADR-13, ADR-19 | экран «что работает сейчас»; отчёт приходит другим участникам |
| 7 | Установка и обновления: инструкция «расширенный режим» + ADB; автообновление с проверкой подписи | ADR-11, ADR-16, ADR-21 | APK с чужой подписью не ставится; обновление доходит через запасной транспорт |
| 8 | Несколько групп на OpenMLS | ADR-3 | 2+ группы из 3+ человек, добавление и удаление участника |
| 9 | Несколько устройств: второй Android, перенос истории | ADR-17 | новое устройство получает историю зашифрованно; удалённое устройство теряет доступ к новым сообщениям |
| 10 | Клиент Windows на общем ядре | ADR-22 | Windows-устройство участвует в чатах 1:1 и группах |
| 11 | Mesh: Reticulum/LXMF через RNode на 2× Heltec V3 по Bluetooth | ADR-18 | доставка между двумя телефонами без интернета; сопряжение проверено на версиях Android участников |
| 12 | Перед релизом — глубокий агентный аудит всего кода, особенно ключей и вызовов libsignal/OpenMLS | ADR-15, ADR-20 | каждая находка закрыта исправлением с воспроизводящим тестом |

Перед шагами 4, 5 и 11 — перепроверить факты по [DOCS-RECHECK-BEFORE-USE]. Модели для ИИ-ревью выбирать по свежим рейтингам — `wiki/references/ai-security-review.md`.

Не входит в MVP (R-4, R-7): вложения и голос, Bluetooth/Wi-Fi рядом без LoRa, Meshtastic и MeshCore, защита при изъятии телефона и маскировка приложения.
