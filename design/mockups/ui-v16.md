# UX v16 — первый подтверждённый обмен

Статус: **предложено, не принято**. Дата: 2026-10-13.

Кликабельный макет: `design/mockups/ui-v16.html`. Самодостаточный HTML: скачать и открыть в браузере, подключение к интернету не нужно. После замечания владельца об отличии стиля макет пересобран из исходного HTML v14: его визуальная система, рамка телефона, SVG, кнопки, строки, шапки и нижняя навигация сохранены; синий акцент и серый текст в светлой теме слегка затемнены для контраста, без смены цветовой схемы; новый отдельный визуальный стиль отклонён. Основа — принятый v14; звонки из предложенного v15 не включены. Существующие макеты не заменены. Код Android в части онбординга следует макету (`fadc34b`, PR #101); Rust не изменён.

## Как смотреть

1. «Мне прислали приглашение» → «Вставить пример» → имя → подтвердить добавление → ожидание. В панели проверки нажать «Второй телефон ответил» → отправить сообщение → «Подтверждение и ответ».
2. «Хочу пригласить близкого» → профиль → подключение организатора. В панели проверки «Действующие настройки» → «Проверить и принять» → создать приглашение. Проверить варианты с кодом и без гостевого доступа.
3. «Мы сейчас рядом» → моделировать завершённый или частичный обмен → подготовить Bluetooth → чат. Отказ в доступе и повторное разрешение доступны в панели проверки.
4. Любой из 20 экранов открывается напрямую в панели сценариев. На телефоне панель расположена под макетом. Тема и текст 200% — настройки просмотра, не экраны приложения.
5. Для проверки ошибок: повреждённый/истёкший текст, неверный код, нет гостевого доступа, несовместимая версия, ошибка локальной записи сообщения, нет маршрута контакта, смена ключа, отказ уведомлений и ошибка чтения хранилища.

Не вставлять настоящие приглашения, пропуски, ключи или сообщения. Прототип хранит демонстрационное состояние в sessionStorage вкладки, не отправляет его по сети. «Начать просмотр заново» очищает только состояние макета.

## Границы и зависимости

- Все подключения, ответы, QR, коды и системные действия **моделируются**. Это не проверка доставки на телефонах.
- Процесс продолжения добавления/различения частичного результата — предложение для проектирования состояний, не доказательство готового backend API.
- Редактирование имени, синхронизация изменений контактам и новая подача отсутствующего маршрута требуют реализации и согласования; этап разрешений перенесён в приложение (PR #101, экран из `ui-v16.html`).
- Флаг завершения мастера не используется как доказательство успешного обмена. Доставка в макете моделируется отдельно; ответ собеседника явно обозначен как демонстрация.
- Нет каталога пользователей, импорта архива, облачного восстановления, работающего второго устройства, нового протокола, автодоверия или обхода подписи.
- Обработчик ссылок не добавлен: принятую ручную вставку сохраняем. Изменение маршрутизации приглашений через ОС потребует отдельного архитектурного решения.
- Не заявляется, что один транспорт работает при любых блокировках; ожидание не называется доказательством офлайна или блокировки контакта.
- Предупреждения об отсутствии копии, несверенном контакте и смене ключа не спрятаны в технических подробностях.

## Проверка макета

Локальный Chromium: интерактивные пути приглашённого и организатора, ошибочный код с сохранением ввода, отказ подписи, сохранение черновика, блокировка при смене ключа, разрешение Bluetooth; проверка ширины 390/1440 px и текста 100/200%. Подготовлены отдельные изображения 20 основных экранов и 15 дополнительных состояний; визуальная проверка выполнена перед публикацией.

Для принятия: просмотр владельцем → корректировки HTML → проверка с 2–5 пользователями на задачах добавления и объяснения статусов → только затем реализация. Для Compose действует отдельная сверка снимков по UI-RENDER-CHECK. TalkBack и реальное поведение Android в HTML не подтверждаются.

Источники проектного контекста: `AGENTS.md`, `wiki/rules/ui.md`, `wiki/architecture/ux.md`, `wiki/architecture/requirements.md`, `wiki/architecture/decisions.md`; статический аудит Android исходников на `8d34cb8`. Документ описывает предложения, не новые факты о внешних сервисах.
